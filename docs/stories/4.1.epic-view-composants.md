# Story 4.1: Epic View et Composants Epic

## Status
Draft

## Story

**As a** project manager using Archon-TRAXIS,
**I want** a dedicated view for Epics with their associated components,
**so that** I can manage Epic-level information and navigate down to Stories within that Epic.

## Acceptance Criteria

1. **Epic View Component**: Create a dedicated `EpicView` component that displays Epic details
2. **Epic Card Component**: Create reusable `EpicCard` component for Epic list displays
3. **Epic Navigation**: Navigation from Project view to Epic view and from Epic view to Stories
4. **Epic CRUD Operations**: Full Create, Read, Update, Delete operations for Epics
5. **Epic Status Management**: Support Epic statuses (todo, doing, review, waiting, done)
6. **Epic Progress Display**: Show calculated progress based on child Stories
7. **Epic Priority Management**: Support Epic priority levels and visual indicators
8. **MVP Flag Support**: Support for MVP flagging of critical Epics

### Data Models
**Epic Interface** (based on backend schema):
```typescript
interface Epic {
  id: string;
  project_id: string;
  title: string;
  description: string | null;
  status: 'todo' | 'doing' | 'review' | 'waiting' | 'done';
  priority: 'low' | 'medium' | 'high' | 'critical';
  mvp_flag: boolean;
  progress?: number; // calculated from child Stories
  created_at: string;
  updated_at: string;
}
```
[Source: BMAD Epic 1 implementation report + Epic 3 MCP extension]

### API Specifications
**Epic Endpoints** (from backend implementation):
- `GET /api/projects/{project_id}/epics` - List Epics for project
- `POST /api/epics` - Create new Epic
- `GET /api/epics/{epic_id}` - Get Epic details
- `PUT /api/epics/{epic_id}` - Update Epic
- `DELETE /api/epics/{epic_id}` - Delete Epic
- `GET /api/epics/{epic_id}/stories` - Get Stories for Epic

All endpoints support ETag caching and follow existing API patterns.
[Source: Epic 2 Backend Services implementation]
