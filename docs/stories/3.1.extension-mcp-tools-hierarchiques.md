# Story 3.1: Extension MCP Tools Hiérarchiques

## Status
**Draft**

## Story
**As a** AI Agent using Archon-TRAXIS via MCP,
**I want** to have dedicated MCP tools for managing EPICs, STORIEs, and SUBTASKs with the same consistency as existing task tools,
**so that** I can effectively navigate and manage the complete BMAD hierarchy without being limited to the current task-only tools.

## Acceptance Criteria
1. **New MCP Tools Creation**: Create 6 new MCP tools following the existing pattern: find_epics, manage_epic, find_stories, manage_story, find_subtasks, manage_subtask
2. **Pattern Consistency**: All new tools must follow the exact same parameter structure, error handling, and response format as existing find_tasks/manage_task tools
3. **Performance Optimization**: Maintain the same performance optimizations (truncation, pagination, counts instead of arrays) implemented in existing task tools
4. **Documentation Integration**: Each tool must have clear documentation for AI usage, including examples and parameter descriptions
5. **Error Handling**: Implement the same MCPErrorFormatter pattern used in existing tools for consistent error responses
6. **Integration Testing**: New tools must be tested with AI agents to ensure they can effectively use them for hierarchy management

## Dev Notes

### Previous Story Insights
From Epic 1 implementation (Stories 1.1-1.3), we have:
- Tables `archon_epics` and `archon_stories` already created with proper relationships
- `archon_tasks` table extended with `story_id` column for BMAD integration
- Recursive functions `get_task_subtasks_recursive()` and `get_task_hierarchy_path()` available
- Subtasks implemented using `parent_task_id` in the same `archon_tasks` table (no separate subtask table)

### MCP Architecture Context
**Source: `python/src/mcp_server/features/tasks/task_tools.py`**

**Existing Tool Pattern:**
- `find_tasks()` - Consolidated list/search/get with parameters: query, task_id, filter_by, filter_value, project_id, include_closed, pagination
- `manage_task()` - Consolidated CRUD with actions: "create", "update", "delete"
- Tools use `FastMCP` framework with `@mcp.tool()` decorator
- All tools return JSON strings with consistent `{"success": true/false, ...}` format
- Error handling via `MCPErrorFormatter.format_error()` and `MCPErrorFormatter.from_http_error()`

**Performance Optimizations to Replicate:**
- Description truncation: `MAX_DESCRIPTION_LENGTH = 1000` with `truncate_text()` function
- Array count replacement: `sources` → `sources_count`, `code_examples` → `code_examples_count`
- Optimized pagination: `DEFAULT_PAGE_SIZE = 10`
- `exclude_large_fields` parameter for MCP responses

### Database Schema Context
**Source: Epic 1 Implementation Reports**

```sql
-- Epic table structure
archon_epics {
  id UUID PRIMARY KEY,
  project_id UUID NOT NULL REFERENCES archon_projects(id),
  title TEXT NOT NULL,
  description TEXT DEFAULT '',
  status task_status DEFAULT 'todo',
  priority INTEGER DEFAULT 0,
  mvp_flag BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
}

-- Story table structure
archon_stories {
  id UUID PRIMARY KEY,
  epic_id UUID NOT NULL REFERENCES archon_epics(id),
  title TEXT NOT NULL,
  description TEXT DEFAULT '',
  status task_status DEFAULT 'todo',
  priority INTEGER DEFAULT 0,
  mvp_flag BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
}

-- Task table (already extended)
archon_tasks {
  id UUID PRIMARY KEY,
  project_id UUID NOT NULL,
  story_id UUID NULL REFERENCES archon_stories(id),  -- BMAD hierarchy link
  parent_task_id UUID NULL REFERENCES archon_tasks(id),  -- Subtask hierarchy
  title TEXT NOT NULL,
  description TEXT DEFAULT '',
  status task_status DEFAULT 'todo',  -- Includes 'waiting' status
  assignee TEXT DEFAULT 'User',
  task_order INTEGER DEFAULT 0,
  feature TEXT,
  -- ... other existing fields
}
```
