# Story 4.6: Extension Drag & Drop pour Hiérarchie

## Status
Draft

## Story

**As a** project manager using Archon-TRAXIS,
**I want** drag & drop functionality extended to work across the entire hierarchy,
**so that** I can reorganize Epics, Stories, Tasks, and Subtasks efficiently through direct manipulation.

## Acceptance Criteria

1. **Epic Drag & Drop**: Drag & drop reordering of Epics within Projects
2. **Story Drag & Drop**: Drag & drop reordering of Stories within Epics
3. **Cross-Level Movement**: Move Stories between Epics, Tasks between Stories
4. **Subtask Integration**: Extend existing Task drag & drop to include Subtasks
5. **Visual Feedback**: Clear visual indicators during drag operations
6. **Drop Zone Validation**: Prevent invalid drops with clear feedback
7. **Undo/Redo Support**: Support for undoing drag & drop operations
8. **Performance Optimization**: Smooth drag operations even with large lists

### API Specifications
**Reordering Endpoints**:
- `PUT /api/epics/reorder` - Reorder Epics within Project
- `PUT /api/stories/reorder` - Reorder Stories within Epic
- `PUT /api/stories/{id}/move` - Move Story to different Epic
- `PUT /api/tasks/{id}/move` - Move Task to different Story
- `PUT /api/tasks/reorder` - Reorder Tasks/Subtasks (existing, extend)

**Validation Endpoints**:
- `POST /api/validate-move` - Validate potential move operation
- `GET /api/{type}/{id}/move-impact` - Analyze move impact

### Validation Rules
**Business Rules**:
- Epics can only be reordered within same Project
- Stories can be reordered within Epic or moved between Epics in same Project
- Tasks can be reordered within Story or moved between Stories in same Epic
- Subtasks can only be reordered within same parent Task
- MVP items cannot be moved to non-MVP parents

**Dependency Rules**:
- Cannot move items that would create circular dependencies
- Cannot move items that would break existing dependency constraints
- Warn user about dependency impacts before confirming moves
