# Story 3.2: MCP Navigation et Dépendances

## Status
**Draft**

## Story
**As a** AI Agent using Archon-TRAXIS via MCP,
**I want** advanced navigation tools to traverse the complete hierarchy and manage dependencies between all levels,
**so that** I can understand project structure, manage complex relationships, and make intelligent decisions about task prioritization and sequencing.

## Acceptance Criteria
1. **Hierarchy Navigation Tool**: Create `get_hierarchy()` MCP tool that provides complete project structure navigation with configurable depth and filtering
2. **Dependency Management**: Create `manage_dependencies()` MCP tool to create, read, update, delete dependencies between any hierarchy levels (EPIC↔EPIC, STORY↔STORY, TASK↔TASK, cross-level)
3. **Intelligent Documentation**: Provide AI-optimized documentation with usage examples, parameter explanations, and common workflow patterns
4. **Integration Testing**: Comprehensive testing with real AI assistants to validate practical usability and effectiveness
5. **Performance Optimization**: Maintain sub-120ms response times for hierarchy queries with large project structures
6. **Dependency Validation**: Implement cycle detection and dependency constraint validation to prevent impossible relationships

### Dependency System Architecture
**Source: Technical Analysis + Architecture Patterns**

**Dependency Types to Support:**
- `blocks` - A blocks B (B cannot start until A is done)
- `depends_on` - A depends on B (A cannot start until B is done)
- `related_to` - A is related to B (loose coupling, informational)
- `precedes` - A precedes B (sequence relationship)
- `follows` - A follows B (sequence relationship)

**Cross-Level Dependencies:**
- EPIC → EPIC (roadmap dependencies)
- STORY → STORY (feature dependencies within or across epics)
- TASK → TASK (implementation dependencies within or across stories)
- Cross-level: EPIC → STORY, STORY → TASK (hierarchical constraints)

**Database Extension Required:**
```sql
-- New table for dependency management
CREATE TABLE archon_dependencies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  from_type TEXT NOT NULL, -- 'epic', 'story', 'task'
  from_id UUID NOT NULL,
  to_type TEXT NOT NULL,   -- 'epic', 'story', 'task'
  to_id UUID NOT NULL,
  dependency_type TEXT NOT NULL, -- 'blocks', 'depends_on', 'related_to', 'precedes', 'follows'
  description TEXT DEFAULT '',
  created_by TEXT DEFAULT 'AI IDE Agent',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  -- Prevent self-dependencies
  CONSTRAINT no_self_dependency CHECK (NOT (from_type = to_type AND from_id = to_id)),

  -- Unique constraint to prevent duplicate dependencies
  CONSTRAINT unique_dependency UNIQUE (from_type, from_id, to_type, to_id, dependency_type)
);
```

### Technical Constraints
**Source: Architecture/Coding-Standards + Performance Requirements**

- **Performance Target**: <120ms for hierarchy queries up to 1000 items
- **Cycle Detection**: Must use efficient algorithms (Kahn's algorithm for topological sort)
- **Memory Optimization**: Lazy loading for deep hierarchies, pagination for wide hierarchies
- **Database Queries**: Optimize with CTEs (Common Table Expressions) for recursive hierarchy queries
- **Error Handling**: Use MCPErrorFormatter for all error conditions
- **Caching**: Consider Redis caching for frequently accessed project hierarchies
