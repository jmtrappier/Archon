# Story 4.4: HierarchyBreadcrumb pour Navigation

## Status
Draft

## Story

**As a** user navigating through Archon-TRAXIS hierarchy,
**I want** a hierarchical breadcrumb navigation system,
**so that** I can easily understand my current location and navigate between Project → Epic → Story → Task levels.

## Acceptance Criteria

1. **Hierarchical Breadcrumb Component**: Create a reusable breadcrumb component showing the full hierarchy
2. **Dynamic Context Display**: Breadcrumb updates dynamically based on current navigation level
3. **Clickable Navigation**: Each breadcrumb segment is clickable for quick navigation
4. **Visual Hierarchy Indication**: Clear visual indicators showing the hierarchy levels
5. **Progress Integration**: Show progress indicators at each hierarchy level
6. **Responsive Design**: Breadcrumb adapts to different screen sizes
7. **Context Preservation**: Maintain navigation context when moving between levels
8. **URL Synchronization**: Breadcrumb reflects and controls URL structure

## Dev Notes

### Previous Story Insights
- Stories 4.1, 4.2, 4.3 created individual view components for Epic, Story, and Task levels
- Each level needs consistent navigation patterns and context awareness
- Existing Task components have drag & drop and filtering that should be preserved
- URL structure needs to support deep linking into hierarchy levels
- React Query is used for data fetching across all components

### Data Models
**Hierarchy Context Interface**:
```typescript
interface HierarchyContext {
  project?: {
    id: string;
    title: string;
  };
  epic?: {
    id: string;
    title: string;
    progress: number;
  };
  story?: {
    id: string;
    title: string;
    progress: number;
  };
  task?: {
    id: string;
    title: string;
    progress: number;
  };
}

interface BreadcrumbSegment {
  level: 'project' | 'epic' | 'story' | 'task';
  id: string;
  title: string;
  progress?: number;
  url: string;
  clickable: boolean;
}
```
[Source: Hierarchy requirements + existing component patterns]

### Component Specifications
**Architecture Pattern**: Shared component in `/src/features/ui/components/`
**Location**: Create navigation components in shared UI location:
```
src/features/ui/components/
├── navigation/
│   ├── HierarchyBreadcrumb.tsx
│   ├── BreadcrumbSegment.tsx
│   ├── HierarchyContext.tsx
│   └── index.ts
└── index.ts (EXTEND)
```

**Context Provider Location**: `/src/contexts/HierarchyContext.tsx`
**Navigation Utilities**: `/src/utils/hierarchy-navigation.ts`
[Source: docs/architecture/source-tree.md + existing UI patterns]

### API Requirements
**No new API endpoints required** - breadcrumb uses data from existing APIs:
- Project details from `/api/projects/{id}`
- Epic details from `/api/epics/{id}`
- Story details from `/api/stories/{id}`
- Task details from `/api/tasks/{id}`

**Progress data** comes from existing progress calculations in each service layer.
[Source: Existing API structure from Stories 4.1-4.3]

### URL Structure Design
**Hierarchy URL Pattern**:
- Projects: `/projects`
- Project Detail: `/projects/{project_id}`
- Epic View: `/projects/{project_id}/epics/{epic_id}`
- Story View: `/projects/{project_id}/epics/{epic_id}/stories/{story_id}`
- Task View: `/projects/{project_id}/epics/{epic_id}/stories/{story_id}/tasks/{task_id}`

**URL Handling**: Use React Router with nested route parameters for hierarchy context.
[Source: Existing routing patterns + hierarchy navigation requirements]
